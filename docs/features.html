Laravel Base

Starter Laravel 12 berisi landing page publik, back office AdminLTE untuk user, role, permission, audit log, dan settings, serta REST API berbasis Sanctum. Modul bisnis ditambahkan di atas fondasi ini.

1Landing page publik

Halaman / tersusun dari section yang diatur di config/landing.php. Section bisa diurutkan ulang atau dihapus tanpa mengubah view.

hero→features→about→testimonials→faq→contact

Dua bahasa

Indonesia dan Inggris. Bahasa diganti lewat /lang/{locale} dan disimpan di session. Teksnya ada di lang/{id,en}/landing.php.

Form kontak

Dibatasi 5 request per menit, ada honeypot dan reCAPTCHA opsional. Pesan dikirim ke email penerima dari Settings, dan notifikasi dashboard tetap dibuat walau email gagal.

Tema dari token

Warna diambil dari token brand-* dan accent di resources/css/app.css. Ikon dari Phosphor, animasi dari AOS.

Identitas dari Settings

Nama, logo, kontak, dan sosial media diambil dari SettingsService::publicProfile(), satu-satunya data settings yang boleh tampil di halaman publik.

2Autentikasi

  • Login admin memakai session guard web. URL login bisa disamarkan lewat env ADMIN_LOGIN_PATH.
  • reCAPTCHA bisa diaktifkan di form login. Aturan validasinya selalu dipasang selama captcha aktif.
  • Login berhasil, login gagal, dan logout dicatat ke audit log.
  • Tamu yang membuka URL internal mendapat halaman 401, bukan dialihkan ke login. Halaman publik dan halaman error tidak menautkan URL login.
  • Setelah login, User::landingRoute() memilih halaman pertama sesuai permission user.

4REST API

Semua endpoint berada di bawah /api dan memakai token Bearer dari Sanctum. Otorisasi dicek di controller dengan Gate::authorize() berbasis policy. Error auth, otorisasi, dan validasi dikembalikan dalam bentuk JSON.

EndpointKeterangan
GET/api/healthHealth check, tanpa login
POST/api/auth/loginMengembalikan token
POST/api/auth/logoutMencabut token
GET/api/auth/meData user beserta role dan permission
CRUD/api/usersFilter: search, role, status, per_page
POST/api/users/{id}/toggle-statusAktif atau nonaktifkan user
POST/api/users/{id}/reset-passwordReset password user
CRUD/api/rolesManajemen role

5Fondasi untuk modul baru

Route→FormRequest→Controller→Service→Model→Blade

CodeGeneratorService

Membuat kode berurutan seperti nomor dokumen. Memakai row lock di code_sequences dan reset tiap bulan.

Blameable + auditFields()

Trait dan macro Blueprint untuk kolom created_by dan updated_by. Model baru memakai UUID dan SoftDeletes.

MailService

Mengirim email dan mencatat setiap percobaan ke email_logs. Kegagalan transport tidak melempar exception; cek status di log yang dikembalikan.

DashboardNotificationService

Membuat notifikasi global dengan tipe, judul, pesan, URL, dan referensi.

Setting (key-value)

Disimpan di cache dan menimpa config app.name, judul dan logo AdminLTE, serta mail.* saat boot.

Halaman error tahan banting

Tidak memakai @vite dan membungkus setiap akses DB atau session dengan rescue(), jadi tetap tampil saat database bermasalah.

7Catatan

Celah yang terlihat

  • REST API hampir tidak punya test. Yang tersentuh hanya /api/health dan satu cek 401 di /api/users; CRUD users, roles, dan permissions lewat Sanctum belum diuji.
  • Belum ada modul bisnis. Repo ini memang dimaksudkan sebagai fondasi.

Checklist saat menambah layar admin baru

  • Permission access-… di MenuAccessPermissionsSeeder
  • Label di PermissionPresenter::MENU_LABELS
  • Baris di RoleMenuAccessTest::MENU_ACCESS_BASELINE
  • Middleware can:access-… pada route
  • Entri menu di config/adminlte.php dengan 'can' yang sama
